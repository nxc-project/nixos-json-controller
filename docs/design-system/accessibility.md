# アクセシビリティ

アクセシビリティは追加の仕上げではなく、画面・コンポーネント・操作フローを設計する際の品質基準です。NXC の対象環境と機能を踏まえ、WCAG 2.2 AA を目安に確認します。

## 知覚できること

- 通常テキストと背景のコントラストは原則 4.5:1 以上、大きな文字は 3:1 以上を確認します。
- UI 部品や意味のあるアイコンは、背景との識別に十分なコントラストを確保します。
- 色だけでインストール済み・処理中・エラーなどを表現せず、テキストや形状を併用します。
- アイコン画像に情報がある場合は代替テキストを付け、装飾画像は支援技術から隠します。
- 拡大・狭いウィンドウでも、文字や操作が欠けたり重なったりしないようにします。

## 操作できること

- すべての操作をキーボードで実行できるようにします。
- Tab 移動順は画面の視覚的な順序と意味の順序に合わせます。
- キーボードフォーカスは明確に表示し、hover だけに操作の手がかりを依存させません。
- アイコンのみのボタンには具体的な accessible name を付けます。
- カルーセルや横スクロール領域は、領域名と操作方法を読み上げ可能にします。
- フォーカス可能な要素を、固定ヘッダーやダイアログの背後に隠しません。

## 理解できること

- ボタン名は実行する操作を説明します。「OK」だけではなく「インストール」「キャンセル」などを使います。
- エラーは何が起きたか、何をすればよいかを伝えます。
- 処理中・成功・失敗などの非同期状態は、aria-live / role=status などを使い適切に通知します。
- 入力欄にはラベルまたは明確な accessible name を付け、placeholder だけをラベル代わりにしません。
- パスワード入力など重要な入力には適切な autocomplete とフォーカス制御を用意します。

## 堅牢であること

- prefers-reduced-motion を尊重し、必須でないアニメーションを減らせるようにします。
- 200% 以上の拡大や、ウィンドウ幅を狭めた状態で主要操作が可能か確認します。
- フォント・アイコンの読み込みに失敗しても、意味や操作が失われない fallback を用意します。

## 現状と確認対象

現行実装では Button / Input に focus-visible のリングがあり、InstallProgressIndicator は status と polite live region を使い、カルーセルは region 名とキーボードフォーカスを提供しています。また、いくつかのモーションは prefers-reduced-motion に対応しています。

一方で、この初期文書の作成時点では、すべての画面のコントラスト測定、キーボードだけでの全操作確認、スクリーンリーダー実機確認を完了していません。InstallButton のパスワードパネルは独自 overlay 実装であり、dialog としての role、フォーカストラップ、閉じた後のフォーカス復帰を継続確認する必要があります。文書化をもって適合済みとは扱いません。
