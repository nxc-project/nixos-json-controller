# アプリ発見・検索

アプリ発見画面は NXC LOUNGE の中心となる画面です。検索を主な入口にしつつ、検索前にはおすすめを見て候補を知ることができます。

## 検索前

- 画面の目的が分かる見出しと短い説明を配置します。
- 検索入力を最も見つけやすい位置に置きます。
- Enter と検索ボタンの両方で検索を開始できるようにします。
- おすすめを検索の代替操作のように見せず、探索の補助として配置します。
- おすすめデータの出典・期間・更新日がある場合は、対象を誤解しない近さで表示します。

## おすすめ

おすすめは全体 featured とジャンル別ランキングで情報密度を使い分けます。各ジャンルでは見出し、件数、順位、人気度、アプリ情報を一定の階層で表示します。

横カルーセルにはスクロール領域名を付け、キーボードフォーカスと左右の移動操作を用意します。操作ボタンはスクロール可能な場合にのみ表示し、端では利用できない方向のボタンを表示しません。

## 検索結果

検索結果は AppCard を使い、同じ順序で情報を比較できるようにします。結果件数・検索時間・ロード状態などが表示される場合、検索入力や結果一覧と意味的に関連づけます。

検索結果が多い場合は VirtualizedAppList などの仮想化表示を使い、一覧全体を一度に DOM へ展開しません。追加読み込みの状態、失敗、再試行、結果が尽きた状態を区別します。

## 状態パターン

| 状態 | 表示 |
| --- | --- |
| カタログ準備中 | 検索できない理由と準備中であることを示す |
| 検索前・おすすめあり | おすすめを表示し、検索入力を主導線にする |
| 検索中 | 操作中と分かる表示を出し、重複要求を避ける |
| 結果あり | 結果一覧と追加読み込みを表示する |
| 結果なし | 検索条件を確認・変更する手がかりを示す |
| エラー | 何の取得に失敗したかと再試行方法を示す |
| 部分データ / fallback | 通常データとの差と制約を明示する |

## ナビゲーション

詳細画面から検索へ戻ったとき、検索語や一覧位置を可能な限り保持します。検索語が変わった場合は古い結果やロード状態を新しい検索結果として見せません。
