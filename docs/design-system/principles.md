# 基本原則

NXC LOUNGE のデザイン原則は、画面の正解を一律に決めるものではなく、複数の実装案で迷ったときに優先順位を決めるための共通言語です。

## 1. 見つけることを妨げない

利用者の目的は UI を眺めることではなく、必要なソフトウェアを見つけることです。アプリ名・説明・アイコン・カテゴリ・タグ・パッケージ ID の情報を、装飾より先に理解できるようにします。

- 検索を主要な入口として、見出しと入力欄を迷わない位置に配置します。
- おすすめは検索の代わりではなく、検索前に発見を助ける補助情報として扱います。
- 一覧では項目ごとの情報順序を揃え、比較に不要な情報を増やしません。

## 2. 状態と根拠を隠さない

NixOS へのインストールは、単なる画面上のトグルではありません。利用者がシステム状態を変更する操作なので、現在の状態・処理中の状態・確認できていない状態を混同しません。

- インストール済みと未確認を同じ見た目にしません。
- 処理中は操作を重複実行できないことを見た目でも示します。
- 成功表示はバックエンドの結果や状態確認に対応させ、先走って完了と表示しません。
- エラーは原因と次の行動を示し、技術的な詳細が必要な場合は確認可能にします。

## 3. 操作の優先順位を明確にする

画面の主操作を一つの視覚的な強さで示し、補助操作は控えめにします。青は主操作・選択・フォーカスの合図として使い、画面全体の装飾色にはしません。

## 4. 技術情報を正確に扱う

Nixpkgs のパッケージ名や属性、バージョン、ホームページ、統計の出典などは、意味を変えずに表示します。技術的な識別子を利用者向けに言い換える場合も、元の識別子を確認できる場所を残します。

おすすめの人気度など、外部統計を表示するときは出典と対象範囲を明示します。Arch Linux の統計を NixOS の利用率のように表現しません。

## 5. 静かな UI で情報の差を伝える

無意味な装飾や色数で注目を集めず、文字の階層、余白、境界線、アイコン、状態ラベルを組み合わせます。必要な情報が多い画面でも、同じ部品は同じ形・同じ間隔・同じ操作で動くようにします。

## 6. アクセシビリティを後付けにしない

キーボード操作、読み上げ、フォーカス表示、コントラスト、動きを減らす設定を画面設計と同時に考えます。色だけで意味を伝えず、ボタンの名前や状態を支援技術からも理解できるようにします。

## 判断の優先順位

迷ったときは次の順で判断します。

1. 誤操作を避け、状態を正確に伝えられるか
2. 目的のアプリを見つけ、比較し、操作できるか
3. キーボード・読み上げ・視認性を損なわないか
4. 既存のトークンとコンポーネントで表現できるか
5. 見た目の新しさや装飾上の好みを満たすか

装飾上の好みが上位の基準を損なう場合は採用しません。
